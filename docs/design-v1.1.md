## #14 設定画面でのバージョン表示とアップデート

### 要件
1. 設定画面にいまのバージョンを出す
2. 新しいバージョンがあるかを自動で調べて出す
3. 新しいバージョンがあれば、そこから適用できる

### 前提（Chrome の制約）
拡張は自分のファイルを書き換えられない。どこまでできるかは導入経路で決まる。

| 導入経路 | 判別（`chrome.management.getSelf()` の `installType`） | 扱い |
|---|---|---|
| Chrome ウェブストア | `normal` | `chrome.runtime.requestUpdateCheck()` で確認し、`chrome.runtime.reload()` で即適用する |
| Releases の zip を展開して読み込み | `development` | **バージョン表記のみ**。更新の確認も外部への通信もしない（決定事項） |

`management.getSelf()` は権限なしで呼べる。ストア版の確認は Chrome 自身の更新経路を使うだけなので、拡張から外部への通信は増えず、PRIVACY.md の変更は不要。

### 設計

**設定画面（options.html）**: 先頭に「バージョン」節を追加する。

```
バージョン  v1.0.0（Chrome ウェブストア版）
            ● 最新です（最終確認 2026-11-06 10:12）      [今すぐ確認]
            ● v1.1.0 があります                           [更新して再起動]

バージョン  v1.0.0（zip 版）                              ← zip 版はこの1行だけ
```

- 設定画面を開いたときに自動で確認する。結果は `storage.local` の `updateCheck: { at, latest, status }` に置き、6時間以内の結果があれば再確認しない（`requestUpdateCheck` は短時間に何度も呼ぶと `throttled` になるため）
- 「今すぐ確認」は間隔を無視して確認する。`throttled` が返ったら「しばらくしてから」と出す

**ストア版の適用（sw.js）**
- `chrome.runtime.onUpdateAvailable` を受けて `storage.local.updatePending = details.version` を書く。このリスナーを登録すると Chrome は自動で更新を当てなくなるので、設定画面で適用されない限りは次回のブラウザ起動時に当たる（現状と同じ挙動）
- 設定画面の「更新して再起動」は `chrome.runtime.reload()` を呼ぶ。SW 経由にせず設定画面から直接呼べる

**適用時の副作用（要対応）**
- 再起動すると、開いているタブの小窓（コンテンツスクリプト）は拡張から切り離されて動かなくなる。新しい版のスクリプトはページを再読み込みするまで入らない
- 小窓が持っている未保存の履歴（`flush()` の前のぶん）は失われる
- → ボタンの横に「開いているページの小窓はページの再読み込みまで止まります」と出し、`confirm()` で確認する
- → 切り離された側の overlay.js は `chrome.runtime.id` が `undefined` になるのを検知して小窓に「拡張が更新されました。ページを再読み込みしてください」と出して描画を止める（いまは例外を握りつぶして止まるだけ）

### 変更ファイル
- `src/options/options.html / .js / .css` — バージョン節
- `src/bg/sw.js` — `onUpdateAvailable`
- `src/content/overlay.js` — 切り離し検知
- `README.md`
- `manifest.json` — 変更なし（権限の追加は不要）

## #15 ログウィンドウの表示場所と大きさ

### 要件
1. デュアルモニター環境で、ログウィンドウを出すディスプレイと位置を設定画面で指定できる
2. ログウィンドウの大きさを設定画面で指定でき、使用中にも変えられる
3. ページ内の小窓は位置を覚えず、表示を ON にするたびに拡張アイコンの近くに出す
4. 表示を ON にしたとき、小窓とログウィンドウのどちらで出すかを設定で選べる

「ログウィンドウ」は、小窓の ⧉ で開く別ウィンドウを指す（確認済み）。いまの PiP と同じく、ログウィンドウを開いている間はページ内の小窓は消え、閉じると戻る。

### ページ内の小窓の位置（方針変更）

| 操作 | いま（v1.0.0） | 変更後 |
|---|---|---|
| 表示を ON にする | タブごとに覚えた位置に出る | 常に右上（拡張アイコンの近く）に出る |
| ドラッグ | 動かせる。位置をタブ単位で保存 | 動かせる。保存しない |
| 表示を OFF にする | 消える | 消え、動かした位置も捨てる |
| ログウィンドウを閉じる | PiP を閉じると覚えた位置に戻る | 右上に戻る |
| ページを再読み込み・移動 | 覚えた位置に出る | 右上に出る |

- コンテンツスクリプトからはツールバーのアイコンの正確な座標は取れない。アイコンはブラウザの右上にあるので、ページ表示領域の右上（`top: 12px; right: 12px`、いまの既定位置）を「アイコンの近く」とする
- `overlay.js` は `cfg.enabled` が false → true に変わったとき、およびログウィンドウを閉じたときに `pos = null` に戻す
- 位置の保存は不要になるので、`sw.js` の `ui-get` / `ui-set` と `storage.session` の `ui:<tabId>`、`tabs.onRemoved` の後始末を削除する。`overlay.js` の `ui-get` / `ui-set` の送信も削除する
- 全画面中は今どおり、全画面の要素の中の右上に出る

### ON にしたときの表示先（既定の表示先）

設定 `display` で、表示を ON にしたとき（アイコンのクリック・設定画面のボタン・自動起動）にどちらで出すかを選ぶ。

| `display` | ON にしたとき | ⧉ / ログウィンドウを閉じたとき | OFF にしたとき |
|---|---|---|---|
| `hud`（**既定**。現行どおり） | 右上に小窓を出す | — / 小窓に戻る | 小窓を消す |
| `window` | ログウィンドウを開く。小窓は出さない | 小窓の ⧉ で開く / 小窓に戻る（表示は ON のまま） | ログウィンドウも閉じる |

- 既定は `hud`。更新した人の見え方を変えないため
- `window` で ON にしたときは Service Worker が `chrome.windows.create` で開く。拡張のウィンドウはユーザー操作がなくても開けるので、自動起動でも使える。**PiP はユーザー操作起点でしか開けないので、`display: 'window'` は常に新しい方式のログウィンドウで開く**（`logWindow.mode` は ⧉ ボタンにだけ効く）
- `display: 'window'` で開いたログウィンドウは、**最後にフォーカスしたブラウザウィンドウの、アクティブなタブ**を追いかけて表示する（`tabs.onActivated` / `windows.onFocusChanged`）。ON にした時点ではどのタブを見たいか決まっていないため。⧉ から開いたログウィンドウは、開いたタブに固定する
- ログウィンドウの開閉状態は Service Worker が `storage.local.logwin = { open, tabId, follow }` に書き、各タブの overlay.js は `onChanged` でそれを見て小窓を出す／消す。ブラウザ起動時（`onStartup`）に `open: false` へ戻す
- ログウィンドウ自体を × で閉じたとき、`display: 'window'` なら表示は ON のまま、追いかけていたタブに小窓が出る。表示ごと消したい場合はアイコンで OFF にする

### 前提（Document PiP の制約）
- `documentPictureInPicture.requestWindow()` に渡せるのは `width` / `height` だけで、**位置は指定できない**（`moveTo()` も効かない）。前回の位置はブラウザが覚えているが、ディスプレイを選ばせることはできない
- PiP のウィンドウは `chrome.windows` からも見えない

→ 位置を指定するには、拡張のページを `chrome.windows.create({ type: 'popup', left, top, width, height })` で開く通常のウィンドウ（以下「ログウィンドウ」）が必要。PiP の「常に最前面」という性質は失うが、全画面の動画とは別のディスプレイに置く用途なので問題にならない。

### 設計

**別ウィンドウの種類を選べるようにする**

| 設定 `logWindow.mode` | 中身 | 位置 | 用途 |
|---|---|---|---|
| `window`（**既定**） | 拡張のページ `src/logwin/logwin.html` | ディスプレイ・位置を指定 | 別ディスプレイに出しておきたい |
| `pip`（現行の方式） | Document PiP。小窓ごと移る | 指定不可 | 同じディスプレイで全画面動画の上に重ねたい |

既定を `window` にするので、v1.0.0 から更新した人も ⧉ の挙動が変わる。CHANGELOG と README に、PiP に戻す方法と合わせて書く。

**設定項目（config.js）**

```js
/** 表示を ON にしたときの表示先。'hud' = ページ内の小窓 / 'window' = ログウィンドウ */
display: 'hud',
logWindow: {
  mode: 'window',       // 'window' | 'pip'
  displayId: '',        // chrome.system.display の id。空 = 小窓を開いたウィンドウと同じディスプレイ
  anchor: 'top-right',  // そのディスプレイ内の置き場所（四隅 / 中央）
  width: 360,
  height: 480,
  rememberLast: true,   // 手で動かした・広げた位置と大きさを次回に使う
},
/** 小窓・ログウィンドウの表示倍率(%) */
scale: 100,
```

**ディスプレイの一覧**: `chrome.system.display.getInfo()` で取る。manifest に `"system.display"` 権限を追加する（インストール時の警告は出ない権限）。設定画面ではディスプレイ名・解像度・プライマリかどうかを並べ、配置のプレビュー（ディスプレイの配置図にウィンドウの位置を描く）を出す。保存したディスプレイが外れていたらプライマリに出す。

**ログウィンドウへのデータの流し方**

```
各フレーム bridge.js ──stats──▶ sw.js ──▶ トップフレーム overlay.js（集計・履歴・描画は今のまま）
                                                    │ 描画した body の HTML と警告数
                                                    ▼
                                        sw.js ──port──▶ logwin.html（表示するだけ）
                                                    ▲
                     ⤓ / 履歴クリア などの操作 ──────┘（逆向きに転送して overlay.js が実行）
```

- 計測・履歴・エクスポートはタブの overlay.js が持ったままにし、ログウィンドウは描画結果を映すだけにする。ログウィンドウを開いている間、ページ内の小窓は DOM から外すが、overlay.js の計測と描画は止めない。overlay.js の描画処理（約300行）を共有モジュールに切り出すより変更が小さく、履歴が2か所に分かれない
- ログウィンドウは開いたタブの `tabId` に紐づく。そのタブが閉じたら「元のタブが閉じられました」と出して、最後の表示を残す
- 渡す HTML は overlay.js が `esc()` 済みのものだが、拡張のページで `innerHTML` に入れることになるので、受け側は MV3 の既定 CSP（インラインスクリプト不可）に加えて、`<script>` / `on*` 属性を落とすサニタイズを通す
- スタイルは `overlay-style.js` の `WRA_STYLE` をそのまま読み込み、`.hud.pip` と同じ「ウィンドウいっぱい」の見た目にする
- `rememberLast` が ON なら `chrome.windows.onBoundsChanged` で最後の位置・大きさを `logWindow.last` に保存する

**拡大縮小**
- 設定 `scale`（50〜200%、10% 刻み）を `.hud` に CSS の `zoom` で掛ける。ページ内の小窓・PiP・ログウィンドウ共通
- 使用中の変更: 小窓のヘッダーに `−` / `＋` を追加して 10% ずつ変える（`storage.local.scale` を書くので設定画面と連動する）
- ログウィンドウ・PiP はウィンドウの端をドラッグして大きさを変えられる（ブラウザ標準）。中身は幅に合わせて広がる

### 変更ファイル
- 新規 `src/logwin/logwin.html / .js`
- `src/bg/sw.js` — ログウィンドウの生成・配置、`display: 'window'` での ON/OFF 連動とアクティブタブの追従、overlay ⇄ logwin の中継、小窓の位置保存（`ui-get` / `ui-set`）の削除
- `src/content/overlay.js` — `mode` による分岐、描画結果の送出、`zoom`、＋/− ボタン、位置を保存せず ON のたびに右上へ戻す
- `src/content/overlay-style.js` — ＋/− ボタン
- `src/common/config.js` — `logWindow` / `scale` と merge
- `src/options/*` — 「起動」節に既定の表示先、「ログウィンドウ」節（ディスプレイ選択・配置プレビュー・大きさ・倍率）
- `manifest.json` — `system.display` 権限
- `README.md`, `store/LISTING.md`（権限の追加理由）, `test/options-preview.html`
